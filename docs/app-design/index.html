Navigation and behavior

  • First call: Home → Add SIP account → Save and connect → Connecting → Registered → enter a destination → Video call or Audio call → Ringing → Connected → Ended.
  • Settings: Settings → SIP account → Connection settings. “Done” returns changes to the account draft; only “Save and connect” reconnects. Leaving an edited draft asks whether to discard changes.
  • Connection: A network/server failure offers Try again. Authentication failure opens the account form with an explanation. Use the actual failure reason; never label every failure as a bad password. A connection timeout must end the loading state and show a retry action.
  • Validation: Require username and domain; keep display name optional. Show “Enter a username” or “Enter a server” below the affected field. Validate port as 1–65535. Keep other values. Password rules follow the provider, not an invented minimum length. Reveal is temporary and off by default.
  • Video: Preview runs only while this screen is open. Front/Back is the proposed default for the next call. The history call preference changes which explicit call action is primary; both audio and video remain available. It never auto-answers or silently enables incoming video.
  • Permissions: On first use, explain the need and then use the native iOS prompt. The drawn screen is for access already denied, not a replacement permission dialog. Recheck access on return from iOS Settings. If microphone access is denied, explain that audio calling needs it and offer Open iOS Settings or Cancel.
  • Incoming: This is an in-app screen. Locked/background calls use the system CallKit interface, not a custom lock screen. Audio-only answering and camera privacy behavior must be verified in implementation.
  • Active call: Mute changes to Unmute with a selected fill and crossed-out icon. Camera off changes to Camera on; hidden remote video uses an avatar and a clear status. Speaker opens available audio routes rather than promising a device that is not connected. Hold preserves prior mute/camera choices when resumed.
  • Keypad: Every tap sends DTMF immediately; the entered sequence is not an editable dial field. Hide keypad returns to the active call without ending it.
  • Call failure: Busy, declined, no answer, and connection lost replace the end summary with the actual reason. Retry stays explicit, never automatic. Disable callback when the SIP account is offline and offer a route to Home.
  • History: Tapping a row opens details, not an immediate call. No records: show “No calls yet” and “Make a call”. No missed calls: show “You’re all caught up” and keep the All calls filter available. Filters, details, and the end summary are proposed UI additions.

Accessibility and layout

Use native controls with at least 44 × 44 pt touch areas, including text links and tab items. Support Dynamic Type by growing rows and moving controls into fewer columns; never shrink text to fit. Forms scroll above the keyboard. Keep the active field visible and provide Next/Done actions. Adapt safe areas to each device. The 390 × 844 frames show one portrait size, not tested device layouts.

VoiceOver reads the caller, connection state, then controls. Announce state changes, not every timer tick. Toggle state is explicit. Focus and disabled states follow the design system. Respect reduced motion. Use icons and text alongside color.

What is existing, and what is proposed?

The reviewed app has account fields, a stored port/transport/video preference, audio and video calling, local preview, call history, and mute/camera/flip/speaker/hold/keypad controls. This design adds a new tab structure and dedicated settings pages. Saved default camera, permission recovery, history filters/details, deferred account changes during calls, explicit audio-only answers, and call summaries are proposals, not verified runtime features.

No resolution, frame-rate, or bitrate controls are offered without an established app API. UDP is shown as the current mode; this proposal does not claim it is the only transport the engine can support. SIP over TLS is unavailable in the current project configuration. Illustrations are placeholders, not real camera captures.
