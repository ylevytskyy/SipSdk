# CONTEXT.md — SipSdk Domain Glossary

Canonical definitions for domain terms across the `sipsdk` repository (`platforms/`, `core/`, and `web/`).

- **AOR (Address of Record)**: The canonical SIP identity URI (`sip:username@domain:port`) registered by a `SipClient` user agent with a SIP registrar.
- **Baresip Core (`BaresipCore.xcframework`)**: The pinned static C library bundle combining `libre` v4.12.0 and `libbaresip` v4.12.0 for iOS device (`arm64`) and Simulator (`arm64`, `x86_64`).
- **Video Mode (`vidmode`)**: Baresip per-call media mode (`VIDMODE_ON` for bidirectional audio+video SDP negotiation, `VIDMODE_OFF` for audio-only).
- **Video Codec (`vidcodec`)**: A Baresip plugin registered in `baresip_vidcodecl()` that encodes outgoing `vidframe` buffers into RTP packets and decodes incoming RTP packets into `vidframe` buffers. In `SipSdk`, `H264` (`packetization-mode=1` and `packetization-mode=0`, profile-level-id `42e01f`) is implemented natively with Apple `VideoToolbox` and `re_h264`.
- **Video Source (`vidsrc`)**: A Baresip capture plugin registered in `baresip_vidsrcl()` (`avcapture`) that supplies `VID_FMT_YUV420P` frames from `AVCaptureSession` on physical devices (or a 30 fps synthetic test pattern on Simulator) to the active video stream and local preview.
- **Video Display (`vidisp`)**: A Baresip rendering plugin registered in `baresip_vidispl()` (`iosview`) that receives decoded remote `vidframe` buffers and renders them onto a `SipVideoView` in the iOS UI.
- **CallKit Bridge (`SipCallKitManager`)**: The iOS system telephony coordinator (`CXProvider` + `CXCallController`) that mirrors incoming/outgoing SIP calls, hold, mute, and DTMF actions between iOS system call UI and `SipClient` using each `SipCall`'s `uuid`.
- **Shared C++ Core (`sip_core`)**: Portable C++17 library encapsulating Baresip v4/libre, user-agent lifecycle, call state machine, re-INVITE recovery, packet loss keyframe handling, and media orchestration.
- **C ABI Boundary (`sip_abi`)**: The flat `extern "C"` export layer providing a stable, zero-overhead FFI contract for higher-level platform bindings.
- **Platform Bindings**: Thin language-idiomatic SDK layers wrapping `sip_abi` (Swift for Apple, Kotlin/JNI for Android, C# for Windows, C++ for Linux).
- **Target Platforms (Phase 1)**: Native operating systems: iOS, Android, macOS, Windows, and Linux. Web (WASM / WebRTC) is explicitly deferred to Phase 2.
- **macOS GUI Sample (`SipSdkMac`)**: Native macOS SwiftUI application providing full telephony controls, dialpad, account registration settings, active call management, and hardware-accelerated video rendering for macOS desktop.
- **Pluggable Media Driver (`media_driver`)**: Abstract C++ / C ABI driver interface in `sip_core` (`IVideoCaptureDriver`, `IVideoRendererDriver`, `IVideoCodecDriver`, and audio equivalents) connecting Baresip plugins to platform-native multimedia pipelines.
- **Turnkey Platform Video Views**: Pre-built UI widgets (`SipVideoView` on Apple, `SipSurfaceView` on Android, `SipVideoPanel` on Windows/Linux) that handle camera capture, hardware acceleration (`VideoToolbox`, `MediaCodec`, etc.), and display without exposing raw frame management to host apps.
- **Client & Call Object Model (`SipClient` / `SipCall`)**: The public SDK topology separating global engine/account lifecycle (`SipClient`) from individual call sessions (`SipCall`), with typed event dispatch marshaled to the platform UI thread via `SipClientListener`.
- **Monorepo Layout**: Unified repository topology housing `core/` (C++17 engine + CMake), `platforms/ios/`, `platforms/android/`, `platforms/desktop/`, and shared integration test runners.
- **Protocol Baseline (Phase 1)**: Signaling over UDP and TCP; NAT traversal via STUN/TURN/ICE; G.711 (PCMA/PCMU) audio; H.264 video. TLS and external third-party codecs (Opus/VP8) deferred to follow-up milestones.
- **Rollout Sequence**: Mobile-first phased plan starting with Milestone 1 (C++ Core Extraction & iOS Parity with zero test regression), Milestone 2 (Android AAR + JNI + MediaCodec), Milestone 3 (Desktop macOS/Linux/Windows), and Phase 2 (Web).
- **SIP over TLS (`transport = "tls"`)**: Encrypted SIP signaling on port 5061 backed by statically linked OpenSSL 3.x (`USE_OPENSSL=ON`) across iOS, macOS/Linux, Android, and Windows, with `verify_tls_cert = true` by default and optional custom CA PEM support.
- **Media Encryption (`media_enc`)**: Per-account SRTP policy (`"none"`, `"srtp"`, `"srtp-mand"`, `"dtls_srtp"`). Defaults to `"srtp-mand"` when `transport` is `"tls"` and `"none"` when `transport` is `"udp"` or `"tcp"`.
- **Wideband Audio (`opus` / `G.722`)**: Bundled `libopus` (`opus/48000/2`) and `G722/16000/1` prioritized ahead of `PCMU/8000/1` and `PCMA/8000/1` in `sip_core`.
- **Call Quality Stats (`sip_call_stats_t`)**: Live RTCP/media telemetry (`rtt_ms`, `jitter_ms`, `packet_loss_pct`, `audio_bitrate_kbps`, `video_bitrate_kbps`, `audio_codec`, `video_codec`, `mos_score`) exposed via pull (`sip_call_get_stats`) and a 2-second push callback (`on_call_stats`).
- **Call Transfer (`REFER`)**: Outgoing blind transfer (`sip_call_transfer`) and attended transfer (`sip_call_attended_transfer` with `Replaces`), with `NOTIFY` (`message/sipfrag`) status updates and explicit app approval (`on_transfer_request`) for incoming `REFER` requests.
- **Multi-Call (Lines)**: Two or more concurrent `SipCall` sessions on the single account of one `SipClient`, with hold, swap, call waiting, a configurable concurrent-call cap, and one audio-active call at a time. Multiple accounts per `SipClient` is a separate, later capability.
- **Android System Calling (`SipTelecomManagerCoordinator`)**: The Android coordinator, built on Jetpack `core-telecom` `CallsManager`, that mirrors SIP calls, hold, swap, mute, DTMF and audio endpoints into Android system call UI, like `SipCallKitManager` on iOS. Requires API 26+.
- **Push Wake-up (`SipPushHandler`)**: Android entry point the host app calls from its own `FirebaseMessagingService` with an incoming-call push payload; it shows ringing UI at once, then registers and links the INVITE by Call-ID, or ends the call as missed after a timeout.
- **Local Audio Conference (`mergeCalls` / `splitCall`)**: One client-side audio-only conference per `SipClient` joining 2 to `max_calls` remote `SipCall` legs on the same account. The conference acts as a single audio group for auto-hold and mute, and pauses video on merged legs.
- **Mix-Minus Audio Filter (`aufilt`)**: Portable C++20 Baresip `aufilt` plugin in `core/` that mixes decoded PCM frames across conference legs (resampling when legs use different sample rates) so each remote peer receives local microphone audio plus all other conference peers minus its own voice.
- **_Avoid_**: Rust-over-C FFI wrapper, Pure-C public consumer API, framework-only wrappers (Flutter/React Native-first before native SDKs), Web/WASM inclusion in Phase 1 scope, software-only codecs across mobile devices, raw-buffer callbacks dumping video rendering onto app developers, flat global singleton with numeric callId functions, premature multi-repo splitting before core stabilization, blocking Phase 1 on multi-platform OpenSSL compilation, building desktop before mobile driver validation, patching `libre` with custom per-OS TLS backends instead of OpenSSL, unencrypted RTP default on TLS accounts, silent auto-dial on incoming `REFER` without app consent, calling multiple accounts per `SipClient` "multi-line" (that is multi-account), rebuilding Baresip prebuilts just to enable `mixminus` when `aufilt_register` is already exported, local video MCU compositing during call merge.
