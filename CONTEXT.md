# CONTEXT.md — SipSdk Domain Glossary

Canonical definitions for domain terms across the `sipsdk` repository (`Sources/SipSdk`, `SipSdk/`, and `web/`).

- **AOR (Address of Record)**: The canonical SIP identity URI (`sip:username@domain:port`) registered by a `SipClient` user agent with a SIP registrar.
- **Baresip Core (`BaresipCore.xcframework`)**: The pinned static C library bundle combining `libre` v4.12.0 and `libbaresip` v4.12.0 for iOS device (`arm64`) and Simulator (`arm64`, `x86_64`).
- **Video Mode (`vidmode`)**: Baresip per-call media mode (`VIDMODE_ON` for bidirectional audio+video SDP negotiation, `VIDMODE_OFF` for audio-only).
- **Video Codec (`vidcodec`)**: A Baresip plugin registered in `baresip_vidcodecl()` that encodes outgoing `vidframe` buffers into RTP packets and decodes incoming RTP packets into `vidframe` buffers. In `SipSdk`, `H264` (`packetization-mode=1` and `packetization-mode=0`, profile-level-id `42e01f`) is implemented natively with Apple `VideoToolbox` and `re_h264`.
- **Video Source (`vidsrc`)**: A Baresip capture plugin registered in `baresip_vidsrcl()` (`avcapture`) that supplies `VID_FMT_YUV420P` frames from `AVCaptureSession` on physical devices (or a 30 fps synthetic test pattern on Simulator) to the active video stream and local preview.
- **Video Display (`vidisp`)**: A Baresip rendering plugin registered in `baresip_vidispl()` (`iosview`) that receives decoded remote `vidframe` buffers and renders them onto a `SipVideoView` in the iOS UI.
- **CallKit Bridge (`SipCallKitManager`)**: The iOS system telephony coordinator (`CXProvider` + `CXCallController`) that mirrors incoming/outgoing SIP calls, hold, mute, and DTMF actions between iOS system call UI and `SipClient` using each `SipCall`'s `uuid`.
- **Shared C++ Core (`sip_core`)**: Portable C++17 library encapsulating Baresip v4/libre, user-agent lifecycle, call state machine, re-INVITE recovery, packet loss keyframe handling, and media orchestration.
- **C ABI Boundary (`sip_abi`)**: The flat `extern "C"` export layer providing a stable, zero-overhead FFI contract for higher-level platform bindings.
- **Platform Bindings**: Thin language-idiomatic SDK layers wrapping `sip_abi` (Swift for Apple, Kotlin/JNI for Android, C# for Windows, C++ for Linux).
- **Target Platforms (Phase 1)**: Native operating systems: iOS, Android, macOS, Windows, and Linux. Web (WASM / WebRTC) is explicitly deferred to Phase 2.
- **Pluggable Media Driver (`media_driver`)**: Abstract C++ / C ABI driver interface in `sip_core` (`IVideoCaptureDriver`, `IVideoRendererDriver`, `IVideoCodecDriver`, and audio equivalents) connecting Baresip plugins to platform-native multimedia pipelines.
- **Turnkey Platform Video Views**: Pre-built UI widgets (`SipVideoView` on Apple, `SipSurfaceView` on Android, `SipVideoPanel` on Windows/Linux) that handle camera capture, hardware acceleration (`VideoToolbox`, `MediaCodec`, etc.), and display without exposing raw frame management to host apps.
- **Client & Call Object Model (`SipClient` / `SipCall`)**: The public SDK topology separating global engine/account lifecycle (`SipClient`) from individual call sessions (`SipCall`), with typed event dispatch marshaled to the platform UI thread via `SipClientListener`.
- **Monorepo Layout**: Unified repository topology housing `core/` (C++17 engine + CMake), `platforms/ios/`, `platforms/android/`, `platforms/desktop/`, and shared integration test runners.
- **Protocol Baseline (Phase 1)**: Signaling over UDP and TCP; NAT traversal via STUN/TURN/ICE; G.711 (PCMA/PCMU) audio; H.264 video. TLS and external third-party codecs (Opus/VP8) deferred to follow-up milestones.
- **Rollout Sequence**: Mobile-first phased plan starting with Milestone 1 (C++ Core Extraction & iOS Parity with zero test regression), Milestone 2 (Android AAR + JNI + MediaCodec), Milestone 3 (Desktop macOS/Linux/Windows), and Phase 2 (Web).
- **_Avoid_**: Rust-over-C FFI wrapper, Pure-C public consumer API, framework-only wrappers (Flutter/React Native-first before native SDKs), Web/WASM inclusion in Phase 1 scope, software-only codecs across mobile devices, raw-buffer callbacks dumping video rendering onto app developers, flat global singleton with numeric callId functions, premature multi-repo splitting before core stabilization, blocking Phase 1 on multi-platform OpenSSL compilation, building desktop before mobile driver validation.
